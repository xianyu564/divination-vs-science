# Contributing Guide

Thank you for your interest in the "Xiangshu Cosmos Playbook" project! We welcome contributions of all kinds.

## 🤝 How to Contribute

### 1. Report Issues
If you find issues or have improvement suggestions, please:
- Use the [Issues](https://github.com/xianyu564/divination-vs-science/issues) page
- Select appropriate labels (bug, enhancement, documentation, etc.)
- Provide detailed problem description and reproduction steps

### 2. Submit Content
If you want to contribute code or content:

#### Content Contributions
- **Slide Improvements**: Optimize design, content, or structure of existing slides
- **Speaker Notes**: Supplement or improve speaker notes
- **Extended Readings**: Add new academic materials or reading materials
- **Translation**: Translate content into other languages

#### Code Contributions
- **Tool Development**: Develop related tools or scripts
- **Template Improvements**: Optimize existing templates
- **Automation**: Improve workflows or automation scripts

### 3. Documentation Improvements
- Improve README files
- Add usage instructions
- Improve comments and documentation

## 📋 Contribution Process

### Step 1: Fork the Project
1. Click the "Fork" button on the project page
2. Clone your fork to local:
   ```bash
   git clone https://github.com/YOUR_USERNAME/divination-vs-science.git
   cd divination-vs-science
   ```

### Step 2: Create Branch
```bash
git checkout -b feature/your-feature-name
# or
git checkout -b fix/your-fix-name
```

### Step 3: Submit Changes
```bash
git add .
git commit -m "Describe your changes"
git push origin feature/your-feature-name
```

### Step 4: Create Pull Request
1. Create Pull Request on GitHub
2. Select correct target branch (usually main)
3. Fill in detailed description explaining your changes

## 📝 Contribution Standards

### Code Standards
- Follow existing code style
- Add appropriate comments
- Ensure code runs properly

### Content Standards
- Use clear and accurate language
- Provide appropriate references and sources
- Follow project guiding principles

### Commit Message Standards
Use clear commit messages, for example:
- `feat: add new speaker notes template`
- `fix: fix link error in README`
- `docs: update contributing guide`
- `style: format code`

## 🏷️ Label Descriptions

- **bug**: Bug reports
- **enhancement**: Feature improvements
- **documentation**: Documentation related
- **good first issue**: Simple issues suitable for beginners
- **help wanted**: Issues needing help
